# @blendsdk/lockstep — Project Guidance

> OpenCode project guidance. CodeOps requirements, plans, and the roadmap live in `codeops/`.

## Overview

- **Type:** Node.js CLI + library (ESM, TypeScript)
- **Purpose:** lockstep versioning, dependency-ordered publishing, AI changelog generation, and
  npm provenance for monorepos
- **Package manager:** npm (`package-lock.json`, `packageManager: npm@12.0.1`)
- **Runtime:** Node.js >= 18
- **Test framework:** Vitest

## Conventions

- ESM throughout: import local modules with the `.js` extension.
- `tsconfig` is strict with `exactOptionalPropertyTypes: true`; optional properties that may hold
  `undefined` must be typed `field?: T | undefined`.
- Keep external SDKs optional: load `openai` and `@anthropic-ai/sdk` through runtime-resolved
  dynamic imports so the tool builds and runs without them.
- Prefer pure, testable helpers and protected-method seams over mocking.
- Test files: `*.spec.test.ts` is the immutable specification oracle; `*.impl.test.ts` covers
  internals. Order: spec → red → implement → green → impl → verify.
- Document every public API and non-trivial internal invariant. Do not reference CodeOps plan or
  RD IDs in code comments.
- Conventional Commits. Scope is the module touched; release commits use
  `chore(release): vX.Y.Z`.

## Release safety

- **Pushing to `master` or `main` triggers `.github/workflows/release.yml`.** It bumps the version
  from conventional commits, generates changelog/release notes, commits, tags, and publishes to
  npm. Never push without explicit user intent.
- Publishing uses npm Trusted Publishing (OIDC). Do not add `NPM_TOKEN` or `NODE_AUTH_TOKEN` to the
  release workflow. The job needs `id-token: write`, Node 22.14+, and npm 11.5.1+.
- Provenance requires `id-token: write` and a `repository` field in every published `package.json`.
- All git operations in `src/lockstep.ts` target the configured repository root, not the process
  working directory.
